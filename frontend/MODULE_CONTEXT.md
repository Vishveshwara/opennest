# OpenNest frontend

- Next.js App Router, React, strict TypeScript, Tailwind and shadcn-compatible Radix components. Exact releases and probes: docs/FRONTEND_DEPENDENCIES.md.
- Server configuration fixes PRIMARY or SANDBOX and API/site origins. No browser header/query selects a backend. Dedicated sandbox paths start /recruiter-sandbox; PRIMARY denies them.
- Public search and detail have their own routes and render listing content on the server. Native GET forms expose dependent filters without JavaScript. Client navigation retains map view and sort focus and combines pending sort and page-size changes. The detail route resolves missing listings before the response starts and shares its request-local read with page metadata.
- Public search/detail server reads are anonymous and no-store. A photo refresh replaces direct storage URLs from the latest public listing and repeats the read if a route update supersedes its input. Browser private calls use credentialed backend sessions and in-memory CSRF. No Next.js authentication/session store exists.
- Response schemas in src/lib/contracts.ts validate external JSON and derive frontend types. Search URLs use the complete backend allowlist and preserve nationwide omission of city.
- Session generation rejects late private responses after identity changes. Contact/owner/review components reset on expiry, logout and persona changes. Never persist private data or OTPs in browser storage.
- Owner/review effect cleanup ignores superseded responses without aborting fetches during navigation/Strict Mode. Initial session network failures show a safe notice; anonymous 401 stays quiet. Only root html attribute hydration warnings are suppressed for extension-injected attributes; descendant checks remain enabled.
- All application data and signed images remain no-store. Next.js uses its immutable policy for fingerprinted static assets. Listing photos use direct storage URLs and bypass the image optimizer. Cache Components and React Compiler are disabled.
- Public maps use the backend's stable 0.02-degree cell-center publicLocation with radiusMeters=2000. Exact owner coordinates stay private; precise public distances are absent.
- MapLibre uses a configured MapTiler browser key and attribution. Before constructing a map, setWorkerUrl explicitly resolves the pinned package worker through new URL with import.meta.url so Next emits a same-origin hashed .mjs asset; automatic detection inside the bundled module is unsuitable. Missing key/provider/WebGL leaves list and numeric-coordinate flows usable. No geocoder or Overpass.
- Exact TweakCN theme preserved in src/theme.json and src/app/theme.css. scripts/sync-theme.mjs reproduces them. Montserrat is locally served under OFL.
- The shared header and footer use 168 px WebP assets with fingerprinted URLs. Next.js uses src/app/icon.png, a 200 × 200 px PNG, for the browser tab icon.
- Listing lifecycle is create PAUSED -> AVIF worker -> direct presigned storage PUT -> complete validation -> explicit publish. Sources <=40,000,000 bytes and output longest side <=2,048 px. The encoder tries for 1 MB and the listing limit is 20 photos. WASM and notices come from pinned @jsquash/avif. Inventory/pause/publish use exact server versions.
- Owners can remove validated photos or permanently delete a listing after confirmation. Removing the last required photo pauses publication. Listing deletion uses the current version and returns to My listings. On version conflict the owner must confirm again. Completed upload jobs retain display metadata without File/Blob payloads.
- Detail maps load after the visitor opens them. The contact panel precedes the map and reviews in mobile reading and focus order.
- Contact status can retry a failed read and refreshes the allowance at Kolkata midnight or on return to a stale tab. Successful reveals update review eligibility for the current listing and session. Review pagination uses the last successful response while a new page is pending or fails.
- Profile checks time out after eight seconds and offer a retry. The header displays a status while a check is pending. The login page offers to continue when the browser already has a session.
- Session rotation after Telegram sign-in or persona selection starts GET /api/v1/users/me immediately. The next mutation fetches fresh CSRF independently.
- Real-store browser harness lives in backend isolation-test sources. It invokes Playwright and supplies only fabricated Telegram/storage providers. Production artifacts contain neither fixture nor control endpoint.
- Setup, checks, limitations and remaining live-provider gates: docs/PHASE5_HANDOFF.md. Hosting remains Phase 6.
- Optional OPENNEST_DEV_LAN_ORIGINS in .env.development.local enables exact private-IPv4 development hosts and same-origin /api/v1/... rewrites to the fixed loopback API. Browser configuration uses a relative API base; server reads retain the configured origin. Production builds and SANDBOX reject this opt-in. npm run check:lan verifies cookies/CSRF/logout/no-store through real browser requests.

- Telegram flow is ten-digit Indian phone with fixed +91 prefix -> self-contact/OTP -> name only for new accounts. Browser prepends +91 for the existing API contract. Existing linked accounts sign in directly. Resend/restart countdowns use server deadlines; CODE_READY retries delivery, CODE_SENT rotates up to three fresh codes after 30s. Code/name stay in component memory only.
- Authenticated header shows the caller fullName beneath My account, truncates long names visually, and keeps the full name in the accessible label/title. Account page also displays fullName.
- WAITING_BOT offers a copyable /start command from the current challenge's existing deep link for already-open Telegram chats. Clipboard failure leaves manual selection available; binding, expiry and signup hide the command. It stays in component memory and never authenticates the browser.
- Initial profile failures stay unavailable with a retry action, separate from signed-out 401; Shell and AuthGate do not offer sign-in for an indeterminate session. Owner status selections remount on URL status changes; normalized double-slash return paths are rejected.
